## Problem statement

A faster F1 car often catches the car ahead and then gets stuck about a second behind it. In the leader's wake, the follower loses downforce, so it is slower in the corners; the tow and DRS give some time back on the straights. Where those effects balance, the "stall gap", decides whether a team should keep attacking or change strategy, for example by pitting early to undercut.

Public tools either ignore this or use a single rule of thumb. The question I set out to answer: how well can simple physics, fitted to public timing data, predict the time a following car loses, and where does it break down?

<div class="note">

This is an analysis of public timing data, not an aerodynamic measurement. Race timing cannot fully separate the wake from other close-range effects. This project is not affiliated with Formula 1 or the FIA.

</div>

- **I cleaned the race data** so that only genuine car-following laps were left. I computed lap-by-lap gaps for every pair of cars from public timing, lap and telemetry data (OpenF1, Jolpica and the TracingInsights archive). I removed safety-car laps, pit laps, blue flags and lapped traffic, and split each circuit into corners and straights using the real DRS zones, so that corner losses and straight-line gains could be modelled separately.
- **I built a physics model of the time lost** on each track segment, so that every term stands for a real effect rather than a free curve fit. For a segment at gap *g*, the time lost is the sum of three effects:

<div class="table-wrap">

| Term | What it represents |
|---|---|
| Δt<sub>wake</sub>(g) | Lost downforce slows the corners, while the tow and DRS give time back on the straights |
| κ<sub>p</sub> · t<sub>clean</sub> · w<sub>s</sub> · exp(−g / 0.35 s) | A close-following acceleration cost |
| Δt<sub>leader</sub> · exp(−g / 1.0 s) | Hold-up inherited from the leader |

</div>

- **I kept the model small on purpose:** **six global fitted numbers and no per-circuit tuning**, so it could not simply memorise each track. The stall gap g\* is where the lap-time loss equals the chaser's pace advantage: P(g\*) = Δ<sub>pace</sub>.
- **I defined one skill score, S,** the share of a no-effect baseline's error that the model removes, so every model and baseline is judged on the same scale. A circuit passes at S ≥ 0.5.
- **I fixed the test design before scoring,** so I could not adjust the model after seeing a result:
  - each of the 16 development circuits held out in turn;
  - 7 circuits sealed until the end;
  - a confirmation test on sessions never used, with a pass bar set in advance;
  - frozen model versions (tagged), so I could not quietly change a model after seeing a score;
  - comparison against public and simple baselines, and against a machine-learning correction.

### The failed forecast, and what I found

Even though my model matches the measured loss curve better, the FIA curve forecasts stall gaps better. I ran a follow-up investigation, which only partly explains why:

- Simple extrapolation with no wake physics did as well as the FIA curve or better (0.32–0.38 s), so the FIA curve's win does not validate it either.
- Faster chasers do stall closer, as the model predicts (ρ = −0.47 over 83 plateaus).
- About 75% of plateaus are queues (1,153 of 1,539), where the car ahead is itself stuck.
- Lap-to-lap gap changes respond to the gap far less than any of the curves predict. I don't know the cause yet.

### How I checked it

- **Out-of-sample testing:** leave-one-circuit-out, sealed circuits and a confirmation set, all with criteria fixed before scoring.
- **Baselines:** a no-effect baseline, a race-simulation clamp, a rule of thumb, a fitted empirical curve and physics with FIA CFD wake figures, so the model's skill has a reference.
- **Machine-learning check:** a machine-learning correction on top of the physics added nothing (S 0.644 vs 0.649), which suggests the physics captures what the data can support.
- **Physics checks:** 11 checks on the model's physics pass, for example that the predicted corner-speed loss matches the corner force balance, that no wake gives no time loss, and that the stall-gap solution lands where the loss equals the pace advantage.
- **Frozen versions:** every scored model was tagged, so results cannot drift after the fact.

## Conclusion

Simple physics with six global numbers describes the **average** time a following car loses quite well: it passed 15 of 16 development circuits when each was held out, and beat a model built on FIA CFD wake figures (mean S 0.59 vs 0.33). But it does **not** forecast stall gaps: on the forecast test I fixed in advance, its error (0.48–0.57 s) was higher than the FIA curve's (0.35–0.44 s), so that test failed. On new data the evidence is weak: the cleanest test, on never-used sessions, passed 2 of 5 and missed the 70% bar.

**Limitations:**

- Race timing cannot isolate the wake from other close-range effects, so the fitted wake is not a direct aerodynamic measurement.
- Performance on new circuits is unproven: the cleanest test (confirmation) passed 2 of 5.
- The model fails to forecast stall gaps, and that disagreement is only partly explained.
- A second version improved development-circuit error slightly (0.351 to 0.347), but it is development-only and untested on held-out data.

**Next steps (planned):** a one-shot test of the frozen model on 2026 races with the pass bar set first, and an interactive strategy dashboard.

## Issues I ran into

- **The stall-gap forecast failed.** The model matches the measured loss curve closely but lost the forecast test to the FIA curve at every horizon. Fitting the average loss and predicting when a gap stops shrinking turned out to be different problems. I reported the failure as it stands and ran a follow-up investigation rather than changing the model after the fact.
- **My first explanations for the failure did not hold.** Looking only at plateaus that closed, the model was still worse than the FIA curve at all four horizons, and splitting plateaus into free leaders and queues did not rescue it either. The one effect I could not explain away is that lap-to-lap gap changes barely respond to the gap; I left that as an open question.
- **I looked at the sealed score too often.** The sealed result (5 of 7) had its headline score viewed eight times across checks, so it is weaker evidence than it looks. I treat the confirmation test on never-used sessions (2 of 5) as the cleanest result, and it missed the bar.
- **The development score is optimistic.** My model choices were made using the 16 development circuits, so 15 of 16 overstates how well it generalises. That is why I kept sealed circuits and a confirmation set separate.
- **Las Vegas only partly passed.** It scored S 0.41, below the 0.5 mark, and had the fewest segment passes of any development circuit (14,314). I kept it in the result rather than tuning the model for one track.
- **More model did not help.** Adding a machine-learning correction did not improve the score (S 0.644 vs 0.649), so I kept the six-parameter physics.
- **A CFD wake did not work.** I tried replacing the fitted wake with a wake from my [F1 car CFD](/projects/f1-car-aerodynamics-cfd/). The follower *gained* downforce, which failed the gate I set in advance, so I left the model unchanged.
